# Host map: T3 Code

T3's injected "T3 Code orchestration" instructions own the mechanics; where they and this
map differ, they win. Tools may load late: try a tool's name once before calling it absent.

| Need | T3 Code |
|---|---|
| Model ids | Tiers: models.yaml. Check them against `orchestrator_capabilities`, once per thread (`search` finds models it omits). Every `t3_thread_launch` sets `modelSelection`; an omitted one inherits the launcher's model, and the guard hooks (`agent-setup`) deny it. |
| Start a helper | Same provider: the native subagent tool with `model`. Another provider, a separate checkout (`isolation:"worktree"`) or background: `delegate_task` with `target.model` and effort in `target.options` (Claude: `effort`; Codex: `reasoningEffort`). With the guard hooks installed (`agent-setup`), a delegation whose model is missing or not in models.yaml, or that has no effort, is denied. |
| Role → `role` | Planner, Strategist, Advisor, Diagnoser → `research`; Designer → `design`; QA → `test` (pass the device's `hostId` and `id`). A builder is a thread, not a delegate. |
| Builder thread | `t3_thread_launch`: `title` "#<n> <ticket title>", `message` = the brief, `modelSelection` `{instanceId, model, options:[{id:"effort", value:…}]}` for the ticket's tier (Codex: `reasoningEffort`), `workspaceStrategy` `{type:"worktree", baseRef:"origin/main", startFromOrigin:true, branch:"<n>-<slug>"}`, `delegatedFrom` `{environmentId, threadId, title}` pointing at the coordinator. The builder reports back with `t3_thread_send` to the coordinator thread, which wakes it. |
| List existing | `t3_thread_list`, `t3_worktree_list`. Same task: `t3_thread_send` with only the new instructions (a busy thread gets it as its next turn; `t3_queue` edits it or promotes it to steer the current run). Each review or re-check is a new `delegate_task`. |
| Wake | A delegate's result arrives (follow its `next`); a builder thread's `t3_thread_send` line arrives as a new turn. Once a result is recorded, `t3_thread_organize` `settle` the child or builder thread so the user's inbox holds only what needs them. |
| Heartbeat | `list_scheduled_tasks` first; then `schedule_task`, `schedule` `{type:"interval", everyMs: <heartbeat_minutes × 60000>}`, `freshSession:true`, `bindToCurrentThread:false`, title "<topic> heartbeat", prompt from section 1.4. Keep its `scheduledTaskId` in the run card; a new owner updates the prompt's thread id; the run's end sets `enabled:false`. |
| Tickets | `list_issues` (`query`, `state`) for the frontier, `read_issue` for body, labels, comments and linked PRs. Blockers the tracker keeps elsewhere (GitHub: `gh api repos/<owner>/<repo>/issues/<n>/dependencies/blocked_by`). |
| New owner | `t3_thread_launch`: `message` = the `takeover` pointer (section 5), `title` = "<topic> (cont.)"; omit `projectId` to inherit yours; set `modelSelection` always, to your own model and effort or to the tier the successor needs (a coordinator: Heavy). Work in a worktree: `workspaceStrategy` `{type:"existing_worktree", worktreePath}`; no project: `scratch:true`. Reply with its `link`, then stop. |
